# 認証可否判定 — Score Verify と景品配布

## 判定結果

**画像リザルトによる自動認証は、当時の Discord DM 人手確認と同等の信頼度では成立しない。**  
したがって **Score Verify による景品解禁案は破棄**し、**アーカイブ HTML 経由の景品譜面（D-Birth）配布は行わない（永久）**。

採用する実装方針は **草案 04 Four Chambers**（回顧・攻略構造の展示）。照合 UI で景品を解く経路は設けない。

## 当時の認証（再現したい要件）

Discord DM で各課題曲のリザルト画像を受け取り、人が確認していた。

| 確認項目 | 内容 |
|----------|------|
| 課題曲の同一性 | 指定曲が揃っているか／別曲を送っていないか |
| 失点 | 課題曲合計の Good・Bad・Miss が Category ライフ条件内か |
| 不正修飾 | Auto Play 未使用か |
| 速度 | 曲速度変更（例: 2.00x）がないか |

## 添付リザルトから読める情報（人手なら確実）

サンプル（Xaleid◆scopiX / AT Lv.18）:

| 要素 | 値 | 判定上の意味 |
|------|-----|----------------|
| プレイヤー名 | nanokuro9908 | 送付者照合の手がかり |
| 曲名 | Xaleid◆scopiX | Complex 課題曲の一つ |
| 難易度 | AT Lv.18 | 譜面指定の確認 |
| Good / Bad / Miss | 0 / 0 / 0 | 失点 0 |
| 速度表示 | 2.00x | **未達条件**（速度変更） |
| ロボットアイコン | Auto Play | **未達条件**（Auto） |

この一枚だけでも、速度変更と Auto の両方で **未達** と判定できる。

## 静的 HTML アーカイブで自動認証が難しい理由

1. **信頼境界がない** — ブラウザ完結の OCR／アイコン検出は、改変画像・DevTools・localStorage 改ざんで迂回できる。Discord 人手確認の代替にならない。  
2. **OCR が不安定** — ゲーム UI フォント、`◆` などの記号曲名、解像度・切り抜き・言語混在で誤読しやすい。  
3. **UI 変更に脆い** — Phigros のリザルトレイアウトや Auto アイコンが変わるとテンプレ照合が壊れる。  
4. **サーバ側の受領・保管・再審査がない** — 公式アーカイブを静的配信する前提では、DM 相当の監査ログを持てない。

補助的に「画像を見て人がチェックする作業画面」は作れるが、それは Verify 案（サイト上で条件達成→景品解禁）ではなく、旧運用のメモツールに過ぎない。

## 方針（実装時の拘束）

- **ハブ＋四室（04）** で Category・課題曲・ライフ・解禁順を展示する。  
- 失点換算や当時の確認観点は **説明文として** 載せてよい。  
- **D-Birth のダウンロード／配布リンクは出さない。** Vault 上の D-Birth が YouTube 誘導等である現状方針と矛盾させない。  
- 自己申告スコア入力で景品を解く機能も作らない（Verify 破棄に含む）。

## 基本数値（展示用・参照）

- 失点: Good −1 / Bad −3 / Miss −5  
- Gimmick ライフ 50: 覚醒 / Glacial brilliance / Crystal brilliance_AT  
- Power ライフ 50: Relative brilliance / Memories Sacrifice / (execute.)  
- Complex ライフ 100: Unraveling Stasis / Xaleid◆scopiX（両方 CLEAR で解禁表示）  
- Invader ライフ 75: Meteoric Impact（Complex CLEAR で解禁表示）  
- 景品: D-Birth（**配布なし**。展示のみ可）
