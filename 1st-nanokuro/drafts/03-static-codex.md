# 草案 03 — Static Codex（静的図鑑アーカイブ）

## コンセプト

照合システムを持たない、読み物・図鑑型の保管 HTML。  
「当時こう攻略した／こう組まれていた」を Category ごとに並べ、課題曲は譜面 Vault への参照リンクに徹する。景品 D-Birth は説明と Vault 誘導のみ（条件達成 UI なし）。

## ページ構成

1. header / hero（「1st Nanokuro Collections」＋一行で Cup 形式だった旨）
2. crumb → Home
3. **通読用の短い導入**（解禁順の説明を図か番号付きリストで）
4. **Category セクション ×4**（常時展開。スクロールで辿る）
5. **景品ノート** — D-Birth（アーカイブ上は配布導線を出さないか、常時 Vault リンクのみ）
6. footer

### 各 Category セクション

- 見出し（第一〜最終）
- ライフ値
- 課題曲のリスト（曲名・任意で難易度メモ）
- 「この段の意味」を一文（例: ギミック重視／力技／複合／最終侵略）

解禁関係は **図解だけ**:

```
[Gimmick]──┐
           ├──▶ [Complex] ──▶ [Invader] ──▶ [D-Birth]
[Power ]──┘
```

## 失点ルールの扱い

- ページ下部か導入内に、換算表を静的に掲載するだけ
- 計算・保存・ロック解除は行わない

## ビジュアル方針

- Vault / Notice に近い落ち着いた plate レイアウト
- TRPG 中世風や 2nd マップ風には寄せない（1st は「競技の記録書」）
- 印刷やスクショしやすい単列

## 向いている場合

- まず情報の正本を HTML に固定したい
- 照合 UI は後回し／不要と判断した場合
- 実装コストを最小にしたい

## 向いていない場合

- 景品解禁を HTML 上で再現したい（→ 草案 02）
- 攻略の「進行感」を画面で出したい（→ 草案 01 / 04）
